# Elevate

Next.js 15 + React 19 + TypeScript 6 monorepo with Tailwind CSS 4 and shadcn/ui.

## Architecture

```
elevate/
├── apps/web/              # Next.js application (pages, routing, data fetching)
│   └── src/
│       ├── app/           # App Router pages and layouts (.tsx)
│       ├── components/    # Page-specific compositions
│       └── lib/           # App-specific utilities
├── packages/ui/           # Shared UI component library
│   └── src/
│       ├── components/    # shadcn/ui-style components
│       ├── hooks/         # Shared React hooks
│       ├── lib/           # Utilities (cn, cva configs, etc.)
│       └── styles/        # Global CSS (Tailwind entry)
├── specs/                 # Feature specifications (generated by spec-kit)
│   └── {###}-{name}/
│       ├── spec.md        # Feature specification
│       ├── plan.md        # Implementation plan
│       └── tasks.md       # Task breakdown
└── .specify/              # Spec-kit configuration
    └── memory/
        └── constitution.md # Project constitution (rules & principles)
```

**Key rules:**

- `packages/ui` owns all reusable UI; `apps/web` composes pages from them
- Import UI via `@workspace/ui/components/*` — no cross-package relative imports
- A component must exist in 2+ views before being elevated to `packages/ui` (YAGNI)

## Getting Started

```bash
# Clone the repository
git clone <repo-url> elevate
cd elevate

# Install all dependencies (uses pnpm workspaces)
pnpm install

# Set up git hooks (husky)
pnpm prepare

# Start the dev servers (apps/web + any package watchers)
pnpm dev
```

The dev server starts at `http://localhost:3000` by default.

### First build

```bash
pnpm build        # Full production build across all packages + apps
pnpm typecheck    # Verify TypeScript compiles cleanly
pnpm test         # Run all tests to verify setup
```

> Corepack may prompt you to download pnpm on first run — this is normal.

### Troubleshooting

- **`pnpm: command not found`** — Run `corepack enable && corepack prepare pnpm@10.33.4 --activate`
- **Port 3000 in use** — Pass `-p` to Next.js: `cd apps/web && npx next dev -p 3001`
- **`husky` hooks not running** — Run `pnpm prepare` from the repository root
- **Build fails on first run** — Make sure you ran `pnpm install` from root (not inside a subdirectory)

## Feature Workflow

All features follow the **Spec-Driven Development** cycle via spec-kit:

1. **`speckit.specify`** — Describe your feature in natural language. Generates a spec in `specs/{###}-name/spec.md`.
2. **Review gate** — Review the spec before proceeding.
3. **`speckit.plan`** — Creates implementation plan with research, data model, and contracts.
4. **Review gate** — Review the plan before proceeding.
5. **Typecheck gate** — Run `pnpm typecheck` to verify TypeScript is clean.
6. **`speckit.tasks`** — Generates a task list with parallelization opportunities.
7. **`speckit.implement`** — Executes tasks in order.
8. **Lint gate** — Run `pnpm lint` to verify code quality.
9. **Build gate** — Run `pnpm build` to verify compilation.
10. **Test gate** — Run `pnpm test` to verify tests pass.

### Branch Convention

```
{type}/{###}-{kebab-case-description}
```

Examples: `feat/001-add-auth`, `fix/002-fix-login-redirect`, `chore/003-update-deps`

Types match Conventional Commits: `feat`, `fix`, `chore`, `refactor`, `docs`, `test`.

## Code Style & Conventions

- **TypeScript strict mode** — no `any`, no `@ts-ignore`, explicit return types
- **Prefer `interface`** for object shapes, `type` for unions/intersections
- **Naming**: PascalCase for components, camelCase for functions/variables, kebab-case for files
- **File organization**: One component per file, match file name to exported component
- **Exports**: Named exports for components, `export type` for TypeScript types
- **Commit messages**: Must follow Conventional Commits spec (enforced by commitlint + husky)

## Component Patterns (shadcn/ui)

Components in `packages/ui/src/components/` use `cva()` for variants and `cn()` for class merging:

```tsx
import { cva, type VariantProps } from "class-variance-authority"
import { cn } from "@workspace/ui/lib/utils"

const buttonVariants = cva(
  "inline-flex items-center justify-center rounded-md ...",
  {
    variants: {
      variant: {
        default: "bg-primary ...",
        destructive: "...",
        outline: "...",
      },
      size: { default: "h-10 px-4 ...", sm: "...", lg: "..." },
    },
    defaultVariants: { variant: "default", size: "default" },
  }
)

interface ButtonProps
  extends
    React.ButtonHTMLAttributes<HTMLButtonElement>,
    VariantProps<typeof buttonVariants> {}

function Button({ className, variant, size, ...props }: ButtonProps) {
  return (
    <button
      className={cn(buttonVariants({ variant, size }), className)}
      {...props}
    />
  )
}

export { Button, buttonVariants, type ButtonProps }
```

## Adding shadcn/ui Components

```bash
npx shadcn@latest add button -c apps/web
```

This adds the component to `packages/ui/src/components/`.

## Testing

Tests are strongly encouraged (soft gate). Guidelines:

- Use Vitest (configured workspace-wide via `vitest.workspace.ts`)
- Co-locate tests with source: `src/component/component.test.tsx`
- Write tests for: public API of packages, complex business logic, component interaction patterns
- PRs with test coverage are prioritized in review

```bash
pnpm test              # Run all tests
pnpm test -- --ui      # Run with Vitest UI
```

## Project Constitution

The full project constitution lives at `.specify/memory/constitution.md` and covers:

- **TypeScript Strict Mode** — No escape hatches, explicit types everywhere
- **Component-First Architecture** — shadcn/ui patterns, package boundaries
- **Monorepo Discipline** — Dependency direction, no circular deps
- **Conventional Commits** — Enforced via commitlint
- **Simplicity (YAGNI)** — No premature abstraction, justify complexity
- **Testing (Soft Gate)** — Encouraged but not blocked
- **Branch Convention** — `{type}/{###}-description`

## Constraints

- `packages/ui` MUST NOT depend on any app package
- Circular dependencies are strictly forbidden
- Every dependency must justify its weight (YAGNI)
- No `any`, no `@ts-ignore` — TypeScript strict mode at all times
